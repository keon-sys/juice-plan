# 여행 계획 앱 설계

## 개요

Kotlin + Spring Boot로 만드는 개인용 로컬 여행 계획 앱. 구글맵 공유 링크로 장소(소스)를 등록하고, 지도 기반 화면에서 일자별 타임테이블에 드래그앤드롭으로 배치한다. 단일 사용자, 단일 여행만 관리하며 데이터는 로컬 H2 파일에 저장한다.

## 목표

- 구글맵에서 공유한 장소를 빠르게 소스로 등록 (이름/좌표 자동 파싱)
- 장소별 예상 소요 시간, 종류(음식점/관광지), 예약 필요 여부와 마감일, 자유 비고 관리
- 지도와 연동된 화면에서 일자별 동선을 시각적으로 구성하고, 날짜별 참고사항을 남길 수 있음
- 비밀번호로 간단히 보호된 로컬 개인용 앱

## 기술 스택

- Kotlin + Spring Boot (Web MVC, Thymeleaf, Spring Data JPA)
- H2 파일 모드 DB (`jdbc:h2:file:./data/juice-plan`), `ddl-auto=update`
- Thymeleaf 서버 렌더링 + Vanilla JS
- Google Maps JavaScript API (지도/마커), 드래그앤드롭은 HTML5 Drag and Drop API 또는 경량 라이브러리(SortableJS 등)
- 별도 인증 프레임워크 없이 세션 기반 자체 구현 (개인용 로컬 앱)
- **사전 준비물**: Google Maps JavaScript API 키 (환경변수/`application.yml`로 주입)

## 아키텍처

- 서버 렌더링(Thymeleaf) 위주 + 필요한 상호작용만 JSON API로 처리하는 하이브리드 구조.
- 페이지2(`/plan`)는 로드 시 전체 소스 데이터와 날짜별 참고사항을 JSON으로 페이지에 임베드하고, 지도 상호작용(뷰포트 필터링, 클릭 강조)은 전부 클라이언트에서 처리해 서버 왕복을 최소화한다. 실제 데이터 변경(배정/해제/순서변경/참고사항 저장)만 경량 API로 자동저장한다.
- 페이지 구성:
  - `/` — 비밀번호 게이트 (최초 설정 또는 로그인)
  - `/sources` — 소스 관리
  - `/plan` — 일자별 동선
  - `/sources`, `/plan`은 공통 레이아웃 + 하단 풋터 탭으로 전환

## 인증 & 네비게이션

- `AppSettings` 단일 행에 비밀번호 해시(BCrypt)를 저장. 소스코드에는 비밀번호 값이 존재하지 않는다.
- `/` 접근 시:
  - 저장된 해시 없음 → 최초 비밀번호 설정 폼(입력 + 확인) 표시. 저장 시 해시되어 `AppSettings`에 저장되고 세션 인증 후 `/sources`로 리다이렉트.
  - 해시 있음 → 비밀번호 입력 폼. 일치하면 세션 인증 후 `/sources`로 리다이렉트. 불일치 시 같은 화면에 에러 표시.
- 인증된 세션 상태에서 `/`에 다시 접근하면 자동으로 `/sources`로 리다이렉트.
- 인터셉터가 `/sources`, `/plan` 및 관련 API에 대해 세션의 `authenticated` 플래그를 검사하고, 없으면 `/`로 리다이렉트.
- 인증은 **브라우저 세션 동안만 유지**된다 (기본 `HttpSession`, 별도 remember-me 쿠키 없음). 브라우저를 닫거나 서버가 재시작되면 재인증이 필요하다.
- `/sources`, `/plan`은 하단 고정 풋터의 탭 2개(소스 관리 / 일자별 동선)로 전환한다. 상단 네비게이션은 없다.

## 데이터 모델

### AppSettings (단일 행)
- `id: Long`
- `passwordHash: String`

### Trip (단일 행)
- `id: Long`
- `startDate: LocalDate`
- `endDate: LocalDate`

### Source
- `id: Long`
- `googleMapsUrl: String` — 원본 공유 링크(참고용)
- `name: String`
- `latitude: Double`, `longitude: Double`
- `placeType: enum { RESTAURANT, ATTRACTION }`
- `durationMinutes: Int`
- `reservationRequired: Boolean`
- `reservationDeadline: LocalDate?` — `reservationRequired=true`일 때만 값 존재
- `memo: String?` — 사용자가 자유롭게 남기는 비고. 형식/길이 제약 없음, 완전히 선택 입력
- `scheduledDate: LocalDate?` — 어느 날짜 타임테이블에 들어갔는지. **null이면 미배정(가용 목록에 존재)**
- `sortOrder: Int` — 같은 날짜 안에서의 순서. 미배정 상태면 의미 없음

### DayNote
- `id: Long`
- `date: LocalDate` (유니크) — 여행 기간 내 특정 날짜
- `memo: String` — 그 날짜에 대한 자유 참고사항

**설계 포인트**
- 여행은 단일 트립만 존재하므로 `Source`에 별도 `tripId` FK를 두지 않았습니다(YAGNI).
- 타임테이블 배정/해제/순서변경을 모두 `scheduledDate` + `sortOrder` 두 필드만으로 표현합니다 — 별도 조인 테이블 없이 단순합니다.
  - 배정: `scheduledDate` 설정
  - 해제(타임테이블에서 뺌): `scheduledDate = null`
  - 순서 변경/이동: 특정 날짜의 소스 목록 전체를 순서대로 받아 `sortOrder`를 0부터 재부여 (다음 섹션에서 API로 설명)
- `sortOrder` 유일성은 DB 제약이 아니라 API 저장 로직에서 항상 해당 날짜의 전체 리스트를 재계산해서 보장합니다.
- `DayNote`는 참고사항을 남긴 날짜에 대해서만 행이 존재합니다 — 여행 기간의 모든 날짜에 미리 빈 행을 만들지 않고, 비고를 지우면(빈 문자열 저장) 해당 행을 삭제합니다.

## 페이지1 — 소스 관리 (`/sources`)

**여행 기간 설정 (페이지 상단, 작은 위젯)**
- Trip이 아직 없으면(최초 실행) 시작일/종료일 입력 폼이 바로 보입니다.
- 설정된 후에는 "여행 기간: 2026-09-01 ~ 2026-09-05 [수정]"처럼 요약 표시되고, 클릭하면 다시 편집할 수 있습니다.

**소스 추가 폼**
1. 구글맵 공유 링크 입력 + "가져오기" 버튼
   → `POST /api/sources/parse-link {url}` 호출
   → 서버가 단축링크(`maps.app.goo.gl/...`)의 리다이렉트를 따라가 최종 URL을 얻고, `/place/<이름>/`와 `@<lat>,<lng>,<zoom>z` 패턴을 정규식으로 파싱합니다.
   → 성공 시: 이름/위도/경도 필드가 자동 채워지고(모두 수정 가능), 작은 미리보기 지도에 핀이 표시됩니다.
   → **실패 시**(리다이렉트 실패, URL에 좌표 패턴 없음 등): "링크에서 위치 정보를 찾을 수 없습니다. 이름과 위치를 직접 입력해주세요"라는 안내와 함께, 미리보기 지도의 핀을 직접 드래그해서 좌표를 지정할 수 있는 수동 입력 모드로 전환됩니다. 이름도 직접 타이핑합니다.
2. 장소 종류: 음식점 / 관광지 (라디오 버튼)
3. 예상 소요 시간: 시간 입력 + 분 입력 (합산해서 `durationMinutes`로 저장)
4. 예약 필요 여부 체크박스 → 체크 시 "예약 마감일" 날짜 입력 필드가 나타남 (체크했는데 날짜 미입력이면 저장 시 검증 오류)
5. 비고: 자유 텍스트 입력(선택, 여러 줄 가능) — 예: "창가 자리 요청", "현금만 가능" 등 사용자가 임의로 남기는 메모
6. 저장 → `POST /sources` → 목록에 추가되고 폼은 초기화됩니다.

**등록된 소스 목록**
- 카드/테이블 형태로 이름, 종류, 소요시간, 예약정보(필요시 마감일), 비고(있는 경우), 배정 상태("미배정" 또는 "9/2 배정")를 보여줍니다.
- 각 항목에 수정(같은 폼 재사용, `PUT /sources/{id}`)과 삭제(`DELETE /sources/{id}`, 확인 후 삭제) 버튼을 둡니다.
- 이미 특정 날짜에 배정된 소스도 여기서 수정/삭제할 수 있으며, 삭제 시 스케줄에서도 함께 사라집니다.

## 페이지2 — 일자별 동선 (`/plan`)

**레이아웃**
- 상단: 날짜 탭 (여행 시작일~종료일 범위로 자동 생성, 예: `9/1 | 9/2 | 9/3`)
- 좌측: 가용 소스 목록 — 미배정(`scheduledDate == null`) 소스 중 현재 지도 뷰포트 안에 있는 것만 표시
- 중앙: 구글 지도 — 전체 소스(배정 여부 무관)의 마커를 항상 표시(종류별 색 구분)
- 하단/우측: 선택된 날짜의 타임테이블 — 배정된 소스를 `sortOrder` 순서로 나열
- **날짜별 참고사항**: 선택된 날짜 탭 근처에 자유 텍스트 영역(textarea)을 두고, 그 날짜에 대한 메모(예: "오전엔 우천 예보", "숙소 체크인 15시")를 남길 수 있습니다. 저장 버튼으로 자동저장하며, 날짜 탭을 바꾸면 해당 날짜의 참고사항으로 내용이 바뀝니다.

**데이터 로딩**: 서버가 렌더링 시 전체 Source + Trip 기간 + 여행 기간 내 날짜별 참고사항(`DayNote`)을 JSON으로 페이지에 임베드합니다. 이후 상호작용은 클라이언트 메모리 배열/객체 기준으로 동작하고, 실제 변경만 서버에 저장합니다.

**상호작용**
- 목록 클릭 → 지도 `panTo` + 마커 바운스로 위치 표시
- 지도 `bounds_changed`(디바운스) → 가용 목록을 뷰포트 내 미배정 소스만 남도록 클라이언트에서 재계산 (서버 왕복 없음)
- 가용 목록 카드를 드래그(또는 클릭)해 선택된 날짜 타임테이블에 추가
- 타임테이블 내 드래그로 순서 변경
- 타임테이블 항목의 "X" 버튼 또는 풀 목록으로 드래그해 제거 → 다시 미배정 상태로 복귀
- 날짜별 참고사항 textarea에 입력 후 저장 버튼 클릭 → 해당 날짜의 메모 저장

**API**
- `POST /api/schedule/day/{date}` — body: 그 날짜의 전체 소스 id 순서 배열. 배열 순서대로 `scheduledDate`/`sortOrder`를 일괄 갱신. **이 배열은 해당 날짜에 대해 authoritative하게 취급되어, 이전에 그 날짜에 배정돼 있었지만 배열에 없는 소스는 자동으로 미배정 처리된다.** 추가/순서변경/다른 날짜로 이동을 이 엔드포인트 하나로 처리한다.
- `DELETE /api/schedule/{sourceId}` — `scheduledDate=null`, `sortOrder=0`으로 초기화.
- `POST /api/day-notes/{date}` — body: `{ memo: string }`. 해당 날짜의 참고사항을 저장(upsert)하며, 빈 문자열이면 기존 기록을 삭제한다.
- 저장 실패 시 토스트 알림 + 드래그 이전 상태로 UI 롤백. 성공 응답 전에는 낙관적 확정을 하지 않는다.

## 에러 처리

- 링크 파싱 실패: 서버는 예외가 아니라 `{success:false}` 응답으로 표현, 클라이언트가 수동 입력 폴백 UI로 전환.
- 인증 실패: 같은 화면에 에러 메시지, 별도 잠금/속도제한 없음.
- 여행 기간 미설정 상태에서 `/plan` 접근: "먼저 여행 기간을 설정해주세요" 안내 + `/sources` 링크.
- 입력 검증: 예약 필요 시 마감일 누락, 여행 시작일 > 종료일 등은 서버에서 검증 후 필드별 에러 메시지 반환. 비고/날짜별 참고사항은 자유 텍스트이므로 별도 형식 검증이 없다.
- 스케줄 API 실패: 토스트 알림 + UI 롤백. 날짜별 참고사항 저장 실패도 동일하게 토스트로 알린다.
- `@ControllerAdvice`로 API는 JSON 에러 응답, 폼 요청은 에러 페이지/플래시 메시지로 일관 처리.

## 테스트 전략

- **단위 테스트** (JUnit5 + MockK): 구글맵 링크 파서(정상/리다이렉트 실패/좌표 없음), 시간·분 → `durationMinutes` 변환, 예약 필요 시 마감일 검증, 일자별 순서 저장 서비스(배열대로 재부여 + 배열에서 빠진 기존 항목 자동 미배정), 날짜별 참고사항 저장/삭제(빈 문자열 저장 시 삭제) 로직.
- **통합 테스트** (`@SpringBootTest` + MockMvc, H2 인메모리 test profile): 인증 플로우(최초 설정/로그인 성공·실패/미인증 접근 차단), 소스 CRUD API(비고 포함), 스케줄 배정/해제 API, 날짜별 참고사항 저장 API.
- **수동 검증**: 지도 클릭 강조, 뷰포트 필터링, 드래그앤드롭, 날짜별 참고사항 입력/전환 등 JS 상호작용은 자동화 테스트 범위 밖이며 실제 브라우저로 직접 확인한다.
